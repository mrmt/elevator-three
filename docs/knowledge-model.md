# elevator-two の音楽知識モデル

## はじめに ― コードの中にある「音楽知識」を分離して考える

elevator-two には、多数のアルゴリズム、確率、パラメータ、音源回路が存在する。しかし、それらを実装の集合としてだけ見ると、このシステムがなぜ音楽として成立するのかが見えにくい。

そこで、現在の実装から一段抽象化し、elevator-two が持っているものを**音楽知識モデル**として整理する。

ここでいう音楽知識とは、音楽理論だけではない。

- 何を守るべきか
- 何なら変えてよいか
- どの時間スケールで判断するか
- 現在の状況をどう分類するか
- 過去の演奏を何をどこまで覚えるか
- どんな条件なら何を鳴らすか
- いつ鳴らさないか
- どの変化なら「同じものの変奏」と聞こえるか

までを含む。

elevator-two は、この知識を使って**状態を観察し、判断し、演奏行為へ変換するシステム**と考えることができる。

## 1. 全体モデル

最も単純化すると、elevator-two は次の循環で動く。

```text
            ┌───────────────┐
            │   音楽知識     │
            │ rules / taste │
            └───────┬───────┘
                    │
                    ▼
┌─────────┐   ┌───────────────┐   ┌─────────────┐
│  記憶    │──▶│   現在の状態   │──▶│    判断      │
│ memory  │   │ musical state │   │ decisions   │
└────▲────┘   └───────────────┘   └──────┬──────┘
     │                                    │
     │                                    ▼
     │                              ┌─────────────┐
     └──────────────────────────────│   演奏行為   │
                                    │ performance │
                                    └─────────────┘
```

重要なのは、乱数はこの図の中心ではないことだ。

乱数は**判断の候補から一つを選ぶ道具**であり、候補そのもの、選んでよい条件、選んではいけない条件は音楽知識によって決められる。

## 2. 知識は六種類に分けられる

現在のelevator-twoの知識は、概念的には六種類に整理できる。

### 2.1 不変条件 ― 守らなければ音楽の骨格が壊れるもの

例:

- 基本の拍子感は4/4に置く
- キックは4つ打ちを基本とする
- 小節頭のベースはルート
- コード外へ出ても調からは外れない
- パターンを毎小節引き直さない
- breakを長く続けない
- DJミックスでベースと和音を二重に重ねない
- リフの応答を無限に連鎖させない

これらは「確率0.8」のような好みではなく、**システムが音楽として自壊しないための境界**である。

### 2.2 語彙 ― 選択できる音楽的な身振り

例:

- フレーズ: plateau / build / break / drop / dub-out
- リフのリズム: quarter / eighth / three / laid / push / syncope
- 遷移: break / morph / DJ mix
- ハーモニー: stab / sustain / jazz
- ドラム変形: 抜き / 食い / double / ghost
- リフ変奏: 移調反復 / 反転 / 追加 / 削除 / rhythm variation

elevator-two は無限の音楽を直接探索するのではなく、**人間が音楽的だと認めた語彙の組み合わせ**を探索している。

### 2.3 文脈依存規則 ― 同じ行為でも場面によって意味が変わる

例:

- buildではシーケンスのdelayを深くする
- 明るいコードではベースをルート寄りにする
- 音程が動かないベースではfilter variationを増やす
- ベース音符が少ない小節ではphaserを足す
- stab群ではリフを落ち着いた型へ寄せる
- funk群ではpushやthreeを好む
- break中にはspark riffを出さない
- dubの1小節ではdryを消すが、delay/reverb returnは残す

この層があるため、パラメータ変更が単なる「値の変化」ではなく**編曲上の意味**を持つ。

### 2.4 確率的嗜好 ― 必須ではないが、その音楽らしさを作るもの

確率は「何でもあり」にするためではなく、複数の妥当な候補のどれを今回採るかに使われる。

例:

- 次のシーンは別群へ80%で渡る
- リフから35%で応答する
- リフ全体を30%で1オクターブ下げる
- フィルが35%で次小節へはみ出す
- industrial noiseの左右を70%で独立周期にする

確率値は音楽的な**癖**として働く。

### 2.5 記憶 ― 過去との関係を作る知識

elevator-twoには複数の時間幅の記憶がある。

- 直近に使ったシーン
- 現在のpattern seed
- ベース旋律のseed
- 偶数／奇数小節の2小節構造
- 直前のspark motif
- motifの寿命
- 呼びかけに対する予定された応答
- 現在の陰陽波の位置

これによって現在の演奏が、過去から独立した乱数列ではなくなる。

特にspark motifは、絶対音程ではなく**和音内の相対的な動き**を記憶する。これは「音そのもの」ではなく「音楽的関係」を記憶している例である。

### 2.6 忘却 ― 同じ知識を永久に使わないための知識

記憶と同じくらい重要なのが忘却である。

モチーフは2〜4回使えば引退する。シーンが変われば捨てる。直近のシーンは次の候補から避ける。

これは、生成システムにとって重要な原則を示している。

> **反復には記憶が必要だが、展開には忘却が必要である。**

## 3. 状態モデル ― アプリは何を「現在」として認識しているか

elevator-two が判断に使う状態は、単一の変数ではない。

```text
GLOBAL
 ├─ 陰陽波の位置
 ├─ BPM
 ├─ key
 └─ user controls

SCENE
 ├─ scene identity
 ├─ group / circuit
 ├─ kit
 ├─ density / glitch tendencies
 └─ scene age

PHRASE
 ├─ plateau / build / break / drop / dub-out
 ├─ phrase position
 └─ layer state

BAR
 ├─ bar number
 ├─ fill?
 ├─ dub?
 ├─ event?
 ├─ bass note count
 └─ transition proximity

MOTIF / PATTERN MEMORY
 ├─ rhythm seed
 ├─ bass seed
 ├─ spark motif
 ├─ motif life
 └─ pending response
```

したがって、同じ16分位置でも、その瞬間の意味は状態によって変わる。

「step 12だから音を鳴らす」のではなく、

> 「陽へ向かっている曙のbuild後半で、8小節の折り返しに近く、ベースは疎で、前の区間にsparkの呼びかけがあった」

という状態を背景に、実際の音が決まる。

## 4. 判断は時間階層ごとに分業される

音楽知識モデルとして見ると、elevator-twoは一つの巨大な判断器ではなく、**異なる時間感覚を持つ複数のエージェント**に近い。

### 4.1 Composer ― 長期構成

時間幅: 20〜40分〜数分

判断:

- 陰から陽へどう移るか
- 次にどのscene familyへ行くか
- 同じ場所に留まりすぎていないか
- BPMやkeyをどう乗り換えるか

目的:

**長く聴いたときに「大きな呼吸」を作る。**

### 4.2 Arranger ― フレーズ構成

時間幅: 8〜16小節

判断:

- plateauを続けるか
- buildするか
- dropするか
- 一瞬breakするか
- dub-outへ行くか
- layerを何枚出すか

目的:

**現在の素材を使って起伏を作る。**

### 4.3 Section editor ― 4〜8小節の句読点

判断:

- fillを入れるか
- filter sweepを入れるか
- kick/hatを抜くか
- glitchを入れるか
- spark riffを呼ぶか
- dubを起こすか

目的:

**長い反復の中に節目を聞かせる。**

### 4.4 Players ― 各楽器の演奏判断

各楽器は同じ生成方式を共有しない。

- drummerは拍の骨格を守る
- bassistは和声と音色の両方を演奏する
- harmony playersは回路ごとに異なる奏法を持つ
- sequencerは少数音を反復しながら空間を開く
- spark playerはモチーフを記憶し変奏する
- industrial layerは小節線から意図的に外れる

目的:

**楽器の役割に応じた自由を与える。**

### 4.5 Mixer / dub engineer ― 音響も編曲として扱う

判断:

- filterをどこまで開くか
- delay feedbackをいつ上げるか
- dryをいつ消すか
- phaserをいつ使うか
- resonanceを上げたとき量をどう補正するか

目的:

**音響操作を「後処理」ではなく演奏行為にする。**

## 5. 判断の基本形は「条件 → 候補 → 制約 → 重み → 行為」

多くの判断は、概念的には次の形に整理できる。

```text
1. 現在の状態を読む
2. 今回選べる候補を作る
3. 音楽的に不適切な候補を除く
4. 残った候補に文脈依存の重みを付ける
5. 必要なら確率で一つ選ぶ
6. 演奏行為へ変換する
7. 必要な記憶を更新する
```

たとえば次のシーン選択なら、

```text
陰陽波の現在位置
      ↓
近いシーンを候補化
      ↓
直近のシーンを除外
      ↓
別群を優先
      ↓
遷移可能性を確認
      ↓
scene決定
      ↓
break / morph / mix を決定
```

spark riffなら、

```text
4小節区間の開始
      ↓
break中ではない?
      ↓
出現間隔を満たす?
      ↓
呼びかけか応答か?
      ↓
scene groupからrhythm profile
      ↓
新規motif or remembered motif
      ↓
variation
      ↓
register / timbre contour
      ↓
配置して演奏
      ↓
motif lifeを更新
```

この形は、将来新しい知識を追加するときの共通フレームとして使える。

## 6. 「音楽的制約」は生成能力を狭めるのではなく、意味を作る

elevator-twoでは制約が非常に多い。

一見すると、生成AI的な自由度を下げているように見える。しかし実際には逆である。

たとえば、

- キックを普段は崩さないから、崩した瞬間が意味を持つ
- breakを短くするから、休止が句読点になる
- motifをそのまま永久反復しないから、再登場が記憶として働く
- リフを常時鳴らさないから、登場が合図になる
- ベースの音程を増やさないから、filter movementが演奏として聞こえる
- DJ mixでdrumsだけを重ねるから、scene transitionが濁らない

つまり制約は「できないこと」ではない。

**差異を知覚可能にするための背景**である。

## 7. 反復・変奏・対比・休止 ― 四つの基本操作

現在の実装を抽象化すると、elevator-twoの編曲は主に四つの操作からできている。

### 反復

pattern seed、bass seed、2小節単位の顔、持続するscene identity。

聴き手に「いま何が鳴っているか」を覚えさせる。

### 変奏

mutate、fill、spark motif variation、filter wobble、octave displacement、rhythmic type。

覚えたものを壊さず、新しさを与える。

### 対比

陰↔陽、stab↔sustain、暗いkit↔electro kit、plateau↔build/drop。

局所的変化では作れない大きな違いを作る。

### 休止

break、kick/hat抜き、dub dry cut。

音を追加せず、欠落によって構造を聞かせる。

この四つを時間階層ごとに組み合わせることが、elevator-twoの編曲の基本文法といえる。

## 8. 音高・リズム・音色・空間を同格の演奏パラメータとして扱う

一般的な自動作曲では、音高とリズムを生成し、その後に音色を当てる構造になりやすい。

elevator-twoでは、これは当てはまらない。

ベースでは、音程が単純ならfilter movementが増える。spark riffでは、旋律と同時にcutoff、Q、decayのフレーズ内輪郭が決まる。dubでは、dryとdelay returnの関係そのものが1小節の演奏になる。buildでは、シーケンスのping-pong delayが深くなり、音像が広がる。

したがって、elevator-twoの「ノート」は概念的には、

```text
note =
  pitch
+ onset
+ duration
+ velocity
+ timbre trajectory
+ spatial behavior
+ structural role
```

として扱ったほうが実態に近い。

## 9. 知識には「由来」と「確信度」がある

DESIGN.mdを見ると、多くの規則は最初から理論的に決められたものではない。

「聴いた結果の指摘から」という記録が何度も現れる。

たとえば、

- breakは16小節では長すぎた → 1小節へ
- ベース旋律が毎小節変わると落ち着かない → seedを保持
- デチューンだけではベースが薄い → PWMを導入
- 持続和音が前に出すぎる → bus levelを下げる
- リフのミクロな揺らぎは耳に届かない → フレーズ単位の音色輪郭へ
- 乱数を増やしても変奏にはならない → motif memoryを導入

つまり、この知識ベースは「音楽理論集」ではなく、**仮説 → 実装 → 試聴 → 修正**で育った経験知である。

将来このモデルを明示化するなら、各知識に次のメタデータを持たせる価値がある。

```text
Knowledge Rule
 ├─ statement      何を知っているか
 ├─ scope          どの時間階層／楽器に効くか
 ├─ condition      いつ適用するか
 ├─ action         何をするか
 ├─ invariant      絶対条件か
 ├─ weight         嗜好ならどの程度か
 ├─ memory         何を参照・更新するか
 ├─ rationale      なぜそうするか
 └─ evidence       試聴・実測・設計判断
```

これは、今後Claude Codeや別のAIと開発を続ける際にも有効である。

## 10. 現在の知識モデルの強み

### 局所ランダムに陥らない

長期波、scene、phrase、bar、stepが分離されているため、16分音符の変化がそのまま曲全体の迷走にならない。

### 楽器の役割が保たれる

全トラックに同じ生成器を使わず、kick、hat、bass、harmony、riffがそれぞれ別の「常識」を持つ。

### 記憶がある

patternとmotifが過去を参照するため、「前に出たものが戻る」が成立する。

### 音響が作曲から分離していない

filter、delay、resonance、stereo imageまで構成要素になっている。

### 人間が介入できる

完全自律ではなく、陰陽、密度、evolution、mutate、scene selection、nextなどで、人間が高位の意図を与えられる。

## 11. 現在のモデルにまだ明示されていないもの

ここからは「現状に存在しない機能」の提案ではなく、**現在の資料からは明示的なモデルとして確認できない領域**を区別しておく。

### 聴覚的な自己評価

現在は「自分が今どのくらい混雑して聞こえているか」「直前の結果が良かったか」を音声解析して判断する仕組みは、資料上の中心モデルにはない。

判断は主として内部状態とルールから行われる。

### 長期的な学習

試聴結果は人間との開発対話を通してDESIGN.mdとコードへ反映されてきたが、実行中のアプリ自身が「この演奏は良かった」と学習してルールを書き換えるわけではない。

### 意味的な曲想

陰陽やscene personalityはあるが、「悲しみ」「緊張から解放」「夜明け」といった物語意味を理解して作曲しているわけではない。名前は人間が与えた音楽的メタファーである。

この境界を明確にしておくと、現在のシステムの強さを過大評価せずに済む。

## 12. 将来の開発で、このモデルをどう使えるか

新機能を「音を増やすIssue」として考える代わりに、次の問いを使える。

1. **これはどの時間階層の知識か？**
2. **どの状態を観察して判断するのか？**
3. **守るべき不変条件は何か？**
4. **候補となる音楽語彙は何か？**
5. **確率に任せる部分と、規則で決める部分はどこか？**
6. **過去の何を記憶する必要があるか？**
7. **いつ忘れるべきか？**
8. **結果は音高・リズム・音色・空間・休止のどこへ作用するか？**
9. **人間の操作はこの判断へどう介入するか？**
10. **試聴して何をもって成功と判断するか？**

この10問に答えられれば、新しい仕掛けも既存の音楽システムへ自然に接続しやすい。

## 13. elevator-two の知識モデルを一文で表す

elevator-twoは、

> **複数の時間階層にわたる音楽状態を保持し、楽器ごとの役割、不変条件、文脈依存規則、確率的嗜好、短期記憶と忘却を使って、反復・変奏・対比・休止をリアルタイムに編成する知識駆動型の自動演奏システム**

と捉えることができる。

ここで最も重要なのは「自動」であることより、**何を知っているから、その判断をしたのかを説明できる**ことだ。

elevator-two の現在の面白さは、ニューラルネットワークの内部に暗黙知を閉じ込めるのではなく、人間とAIの対話で得た音楽的判断を、かなりの部分まで明示的な規則としてコードに残している点にある。

それは同時に、次にどんな音楽知識を教えるべきかを、人間が考え続けられる構造でもある。
